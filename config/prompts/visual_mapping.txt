Rules:
- Exactly {scene_count} scenes, scene_id {scene_id_start}..{scene_id_end}
- **diagram_type is REQUIRED** on every scene — never leave blank
- **diagram_prompt is REQUIRED** — internal production note only (never shown on screen); describe the visual story
- **diagram_labels** — short text on arrows/boxes (max 6 words each):
  - memory_layout: ["RAM", "contiguous block", "address 0x000"]
  - array_access: ["base address", "base + index × size", "target element"]
  - linked_nodes: ["Head", "Node A", "Node B", "null"]
  - tree_nodes: ["root", "left child", "right child"]
  - stack_heap: ["Stack (LIFO)", "Heap (dynamic)"]
  - warning_icons: ["consequence 1", "consequence 2", "consequence 3"]
  - flow_steps: ["step 1 label", "step 2 label", "step 3 label"]
  - comparison: ["left option", "right option"]
  - http_request: ["GET /api/users", "200 OK + JSON body"]
  - http_cache: ["GET + If-Modified-Since", "304 Not Modified (no body)"]
  - http_redirect: ["GET /old-page", "302 Redirect", "GET /new-page"]
  - status_code / errors: can be empty — code comes from visual_title
- diagram_type guide:
  - memory_layout: contiguous RAM, allocation, address space
  - array_access: index math, lockers, O(1) lookup
  - linked_nodes: pointers, next node chains
  - tree_nodes: binary trees, parent/child hierarchy
  - stack_heap: stack vs heap memory regions
  - warning_icons: consequences, failures, costs of wrong choices (NOT generic lists)
  - http_request: any request/response exchange
  - http_cache: 304, ETag, browser cache hits
  - http_redirect: 301, 302, Location header
  - http_error_client: 400–499
  - http_error_server: 500–599
  - status_code: defining one specific status code number
  - comparison: X vs Y side-by-side
  - flow_steps: multi-step pipeline (use for processes with 2–4 steps)
  - list_items: ONLY for simple enumerations where bullets ARE the content
  - concept: LAST RESORT — almost never use; if you pick concept the slide will look broken
- For data structure / CS topics, prefer memory_layout, array_access, linked_nodes, tree_nodes over generic flow_steps
- **visualization** (preferred for CS): describe STATE CHANGES, not animation commands
  - AI describes *what changed*; the engine computes *how* it animates
  - Use **transitions**: list of states A→B→C (each state = memory snapshot)
  - Or use **events**: semantic vocabulary — Allocate, Visit, Highlight, Compare, Swap, Shift, Insert, Write, Link, Caption
  - State fields: array (memory cells), addresses, basePointer, activeIndex, highlight (indices), caption
  - Use null or "_" for empty memory slots during insertion
  - Example insertion: [10,20,30,40] → [10,20,null,30,40] → [10,20,25,30,40]
  - NEVER emit pointer_move, shift, swap as animation ops — only as state or events
  - If omitted, presets generate transitions from diagram_type
- visual_bullets should complement the diagram, NOT duplicate it verbatim
- visual_title = concept being defined in that beat
- accent_color palette: #3B82F6 blue, #10B981 green, #F59E0B amber, #EF4444 red, #8B5CF6 purple, #06B6D4 cyan
- music_mood: calm | focus | example | recap | transition
- Keep visual_title SHORT — one line at 64px
